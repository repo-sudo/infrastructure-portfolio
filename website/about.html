Purpose / 03

About this lab

This is a personal infrastructure learning lab used to practise server administration, network segmentation, firewall policy, deployment automation, and recovery habits in a small but realistic environment.

\n
VIEW LAB TOPOLOGY ↓

Why I built it

I am using hands-on projects to build practical infrastructure skills across Linux, Windows Server, networking, virtualisation, automation, and cloud.

How I work

I build the system, test it, break parts of it, fix the issue, then document the commands, decisions, and lessons in GitHub.

Current stack

  • HP Z2 SFF host
  • Proxmox VE hypervisor
  • TP-Link Omada SG2008P managed switch
  • OPNsense firewall/router VM
  • VLAN 10 for web services
  • VLAN 20 for home-control services
  • VLAN 30 for infrastructure services
  • Linux and Windows Server virtual machines
  • Nginx static website on web01
  • PowerShell and SSH-based deployment workflow

AI assistance

AI is used as a learning assistant for planning, command explanation, troubleshooting, and documentation. The lab work is still manually executed, tested, and verified.

The environment is intentionally small, but the workflow mirrors real infrastructure habits: change control, verification, configuration backups, restore planning, firewall rules, segmented networks, SSH key-based access, automation, and clear documentation.

Architecture / 04

Lab topology

OPNsense separates the home network from three purpose-built VLANs and controls permitted access between them.

The HP Z2 runs Proxmox and hosts OPNsense, web01, hch01, and dns01. All access to the lab VLANs passes through the OPNsense VM. The diagram omits addresses, VPN configuration, management endpoints, and camera connection details.
