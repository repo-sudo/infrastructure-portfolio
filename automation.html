Automation / 01

Automation in the lab

This page tracks the repeatable workflows that keep the lab easier to update, verify, and recover. The goal is not to automate everything at once; it is to remove fragile manual steps where they already caused mistakes or wasted time.

Current work focuses on website deployment, GitHub publishing, monitoring checks, backup routines, and small scripts that make operational tasks consistent.

Deployments
Website updates are pulled from GitHub and pushed to the internal web server.
Publishing
GitHub Pages provides the public HTTPS mirror while web01 remains the lab target.
Checks
Pages and services are verified after changes instead of assuming a deployment worked.
Recovery
Backups and restore tests are documented so recovery is repeatable, not improvised.

Principles / 03

How I use automation

Automate after the manual path is understood

I first learn the task by doing it manually, then script the parts that are repetitive, easy to forget, or likely to fail under pressure.

Verify the result, not only the command

A script is only useful if it confirms the service, file, or page was actually updated. The lab is moving toward checks that prove the outcome.

Keep scripts readable

The automation should be simple enough to troubleshoot later. Clear commands and visible status messages matter more than clever shortcuts.

Document what changed

Automation belongs in the project record: what it does, why it exists, what it verifies, and where it still needs improvement.
