Standards / 04

What counts as useful automation

It should remove a real friction point

  • Repeated commands that are easy to mistype.
  • Checks that are easy to forget after a change.
  • Recovery steps that need to work under pressure.

It should prove the result

  • Do not just report that a command ran.
  • Check the service, file, page, backup, or route afterwards.
  • Document what failed and what the script now protects against.
